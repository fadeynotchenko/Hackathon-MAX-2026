# Возможности

Каждая возможность описана одной строкой. «Готово» значит, что она работает на проде, «Не начато»
значит, что она стоит в бэклоге [docs/PRODUCT.md](docs/PRODUCT.md)

## Документы и шаблоны

| #   | Статус | Возможность                                                                                              |
| --- | ------ | -------------------------------------------------------------------------------------------------------- |
| 1   | Готово | 16 стандартных бланков DOCX по образцам: три счёта, три КП, шесть договоров оказания услуг и четыре акта |
| 2   | Готово | Итоговый файл собирает шаблонизатор по бланку, языковая модель в сборке не участвует                     |
| 3   | Готово | Форма разбита на разделы «Ваша организация», «Клиент» и «Условия», у каждого значения виден источник     |
| 4   | Готово | Номер нового документа подставляется сам, следующим после последнего у той же организации                |
| 5   | Готово | Позиции заполняются таблицей с количеством, единицей и ценой, итог и сумма прописью считаются сами       |
| 6   | Готово | Предпросмотр показывает лист ровно таким, каким будет PDF, со всеми подставленными значениями            |
| 7   | Готово | Документ собирается в PDF и DOCX, пустые необязательные поля остаются линиями, чтобы вписать от руки     |
| 8   | Готово | Подпись и печать загружаются в профиле картинками и встают на линию подписи в PDF и DOCX                 |
| 9   | Готово | Бот присылает готовый файл в личный чат MAX вместе с сопроводительным текстом                            |
| 10  | Готово | История документов показывает, что, кому и когда отправлено и дошло ли, с поиском по клиенту и виду      |
| 11  | Готово | «На основе этого» берёт прошлый документ за основу нового со свежими реквизитами из карточек             |
| 12  | Готово | «Сделать акт» закрывает счёт, договор или КП актом с теми же сторонами, позициями и суммой               |
| 13  | Готово | Свой шаблон делается из DOCX или PDF: места для данных находят метки `{{…}}`, помощник или правила       |
| 14  | Готово | Чужой документ можно загрузить и поменять в нём данные, сохранив оформление файла                        |

## Реквизиты и контрагенты

| #   | Статус | Возможность                                                                                         |
| --- | ------ | --------------------------------------------------------------------------------------------------- |
| 15  | Готово | В профиле хранятся реквизиты нескольких своих организаций, одна из них основная                     |
| 16  | Готово | Карточки контрагентов заводятся один раз и дальше подставляются в документы                         |
| 17  | Готово | Сервер проверяет ИНН, КПП, ОГРН, БИК и счёт с ключом по БИК до того, как документ уйдёт контрагенту |
| 18  | Готово | Форма подсвечивает неверный реквизит, как только человек уходит с поля                              |
| 19  | Готово | Подсказки DaData заполняют организацию по названию или ИНН, банк по БИК и адрес по первым словам    |
| 20  | Готово | Кнопка демо-данных заполняет форму правдоподобными реквизитами с верными контрольными суммами       |

## Помощник

| #   | Статус | Возможность                                                                                       |
| --- | ------ | ------------------------------------------------------------------------------------------------- |
| 21  | Готово | Документ можно заказать одним сообщением боту: он сам выбирает шаблон и заполняет поля            |
| 22  | Готово | Поля заполняются из текста, с фото или скана карточки и из голосового сообщения                   |
| 23  | Готово | Скан PDF без текстового слоя читается по картинкам страниц, а не отклоняется                      |
| 24  | Готово | Документ правится в чате фразами вроде «поменяй срок на 10 дней», без возврата в форму            |
| 25  | Готово | Всё, что предложил помощник или распознало фото, ждёт подтверждения кнопкой «Всё верно»           |
| 26  | Готово | Помощник берёт значения только из слов человека, придуманное без опоры на сообщение отбрасывается |
| 27  | Готово | Помощник отвечает на вопросы по документу и пишет сопроводительное письмо контрагенту             |
| 28  | Готово | Последнюю правку помощника отменяет кнопка «Отменить» или слова «верни как было»                  |
| 29  | Готово | ИНН из сообщения сам подтягивает из реестра название, КПП, ОГРН, адрес и руководителя             |
| 30  | Готово | Неуверенно прочитанное с фото помечено в чате, а в мини-аппе стоит первым на проверке             |
| 31  | Готово | Длинный образец своего шаблона читается частями, промахи помощника исправляет второй проход       |
| 32  | Готово | Набор из 19 проверочных примеров меряет качество помощника на настоящей модели одной командой     |

## Вход, админка и надёжность

| #   | Статус | Возможность                                                                                              |
| --- | ------ | -------------------------------------------------------------------------------------------------------- |
| 33  | Готово | Внутри MAX мини-апп входит сразу по initData, без лишней попытки обновить сессию                         |
| 34  | Готово | Экран «Метрики» показывает пользователей, документы, воронку до отправки, долю автозаполнения и ошибки   |
| 35  | Готово | В метриках видны прогоны помощника по каналам с долей удачных ответов и временем ожидания модели         |
| 36  | Готово | Конвертации LibreOffice идут очередью, поэтому превью шаблонов не падают с «Cannot fork»                 |
| 37  | Готово | В логах видно, что помощник записал, отклонил или отбросил, без самих значений полей                     |
| 38  | Готово | Сценарий DATA-API из 16 проверок прогоняется против приложения в тестах и проходит официальный валидатор |
