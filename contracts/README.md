# Контракты между сервисами

Единственное, что сервисы репозитория разделяют. Никаких импортов исходников
одного сервиса из другого: только эти артефакты плюс инфраструктура (Redis,
HTTP через gateway).

| Файл                 | Владелец                         | Потребитель                                 | Как обновить                                                                                         |
| -------------------- | -------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `openapi.json`       | `core` (FastAPI)                 | `web` → `src/api/schema.d.ts`               | `cd core && uv run python -m core.scripts.export_openapi`, затем `pnpm --filter @maxapp/web gen:api` |
| `events.schema.json` | `core` (`core.events.contracts`) | `bot` → тест `bot/src/events/codec.test.ts` | `cd core && uv run python -m core.scripts.export_event_schemas`                                      |

Файлы генерируются, руками не правятся. Замки `core/tests/repo/test_generated_artifacts.py`
и pre-commit падают, если артефакт отстал от кода.

## Правила изменения

- Добавить поле или событие можно молча: потребители со старой схемой
  продолжают работать (payload события — `extra="forbid"` на стороне core,
  поэтому поле сначала появляется в контракте, потом в отправителе).
- Переименовать или удалить поле, поменять тип, статус ошибки или форму
  конверта — только с новой версией: `ENVELOPE_VERSION` для событий,
  `/api/v2` для HTTP. Старая версия живёт, пока не обновлён последний потребитель.
- Каждое изменение контракта — отдельный коммит с обновлёнными артефактами и
  тестами обеих сторон.
