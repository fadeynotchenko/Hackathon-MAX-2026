# Контракты между сервисами

Единственное, что сервисы репозитория разделяют. Исходники одного сервиса другой
не импортирует: только эти артефакты и инфраструктура (Redis, HTTP через gateway)

| Файл                 | Владелец                         | Потребитель                                | Как обновить                                                                                         |
| -------------------- | -------------------------------- | ------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| `openapi.json`       | `core` (FastAPI)                 | `web`, файл `src/api/schema.d.ts`          | `cd core && uv run python -m core.scripts.export_openapi`, затем `pnpm --filter @maxapp/web gen:api` |
| `events.schema.json` | `core` (`core.events.contracts`) | `bot`, тест `bot/src/events/codec.test.ts` | `cd core && uv run python -m core.scripts.export_event_schemas`                                      |

Файлы генерируются, руками не правятся. Замок
`core/tests/repo/test_generated_artifacts.py` и pre-commit падают, если артефакт
отстал от кода. Тот же `openapi.json` использует `DATA-API.yaml`: тест
`core/tests/api/test_data_api.py` сверяет, что каждый путь и метод сценария в нём
есть

## Правила изменения

| Изменение                                                                     | Как                                                              |
| ----------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| новое поле или событие                                                        | сразу: потребители со старой схемой продолжают работать          |
| переименовать или удалить поле, сменить тип, статус ошибки или форму конверта | новая версия: `ENVELOPE_VERSION` для событий, `/api/v2` для HTTP |

Payload события на стороне ядра объявлен с `extra="forbid"`, поэтому поле сначала
появляется в контракте, потом в отправителе. Старая версия живёт, пока не обновлён
последний потребитель. Каждое изменение контракта идёт отдельным коммитом с
обновлёнными артефактами и тестами обеих сторон
